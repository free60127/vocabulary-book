# 单词本 · Vocabulary Book

查一个单词、短语或句型，得到一份**能直接用**的详细讲解：意思与词性、褒贬色彩、情感强度、
语域、词根词缀拆解、助记画面、适用场景与**不该用的场合**、近义词逐个讲清差别、
体现差别的例句。存进自己的单词本，按**间隔重复（SM-2）**安排每日复习，还能一键出题自测。

> 与「回译本」（Back-Translate Studio）是同一套基础设施与设计语言的姊妹项目：
> 账号、云同步、AI 接入设置、任务轮询、限流与安全边界全部沿用那边已经跑过测试的实现。

## 跑起来

    npm install
    cp .env.example .env      # 填 AI_API_KEY（Base URL / 模型按需改）
    npm run server            # 后端 http://localhost:8790（同时托管打包好的前端）
    # 开发模式另开一个终端：
    npm run dev               # 前端 http://localhost:5173，/api 已代理到后端

没有 Key 时也可以在「AI 设置」里临时填自己的（只存本机浏览器）。

## 几个关键设计（都是踩过的坑）

- **排期与词条分开存**：词条是"内容"（会同步、会导出分享），排期是"我练到哪了"。
  分开之后把词条拷给同学不会连带把复习进度带过去。
- **Upstash 免费档只给 1 个库**，所以本项目与回译本共用同一个 Redis 是**预期用法**（键前缀已隔离，
  账号/同步/任务/额度四块互不重叠，有测试钉着）。共用意味着**配额也共享**：
  任务记录以前只靠 TTL 过期、条数上限只在 `/api/status` 里报了个数没有真淘汰，
  现在补上了指针式淘汰（`server/job-evict.mjs`）——它不扫键空间，一次只淘汰一条。
- **收藏夹存的是"待办"而不是半成品词条**：近义词那一行只有一行的信息，凑不出完整卡片 ——
  直接塞进本子会得到一堆半成品。所以收藏项 = 词头 + 已知上下文，**查过之后再把完整词条挂上去**，
  那时「加入词库」一步完成（没查过的点「查后加入」，一次点击把查词和入库都做完）。
  删除同样留墓碑，否则删掉的收藏会在下一次同步里被云端旧副本复活。
- **PDF 导出走"隐藏的打印页 + 浏览器另存为 PDF"**：不引入 jsPDF/puppeteer，且 PDF 里的内容和屏幕上是
  **同一个组件**（卡片以后加了新板块，导出自动跟上）。屏幕上看不见（`.print-sheet{display:none}`），
  点导出时给 `body` 加 `printing`，靠 `@media print` 只显示这一块 ——
  比"打印当前页面 + 一条条 display:none 藏东西"可靠：后者加一个新按钮就会漏一个。
  有 11 项测试用 `page.pdf()` 真的生成 PDF 来验证（打印样式只在 print 媒体下生效，
  普通点击测试抓不到"打印出一张白纸"这类问题）。
- **手机端打印预览会按"设备宽度"排版再缩放到纸张** —— 内容一旦比设备宽，整页就被缩小，
  表现为"排版怪异、字突然变小"。所以打印 CSS 里把纸张（`@page size: A4`）、宽度、
  文字缩放（`text-size-adjust`）、长内容换行全部钉死；例句行原来是 `flex-shrink: 0`，
  长例句永远不收缩，实测手机 print 媒体下整页 518px / 视口 412px（溢出 106px），已修。
  另外手机端 `window.print()` 直接弹系统打印界面，"存成文件"藏在右上角 ⋮ 菜单里，
  导出前会先弹一句说明 —— 否则用户看到"未选择打印机"会以为功能坏了。
- **Redis 键一律带应用前缀**：账号与云同步模块是从姊妹项目搬来的，两边前缀原本**写死成同一个**
  （`bts:acct:` / `bts:sync:`）。共用同一个 Upstash 库时会串库 —— 同一个邮箱互相占位，
  账号里存的同步码还会让两个应用读写同一份快照文档（结构不同，合并会清掉对方数据）。
  现在收到 `KV_PREFIX`（默认 `vb:`）一处管理，有测试钉着四个命名空间互不重叠。
- **删除留墓碑**：云同步是并集合并，删除不留标记就会"删了又出现"。
  墓碑过滤做成**合并之后的统一收口** —— 第一版只在本子已存在那条分支里判断，
  新本子走"整体加入"那条路时墓碑完全失效（有测试钉着）。
- **单条过大丢弃、超长字段截断**：一条脏数据不该卡住整次同步。
- **服务端生成词条 id**：客户端靠它做合并、去重、删除墓碑；模型不给也不该让它给。
- **查词走异步任务 + 轮询**，不是长连接：手机端/弱网下长请求会被挂起甚至中断。
- **自定义 Base URL 禁私网 + 不跟随重定向**：防 SSRF（含 IPv4 映射的 IPv6 这种绕过）。
- **API Key 归一化**：把粘贴时混进来的非 ASCII 字符/空白清掉（否则会抛一句看不懂的英文错）。
- **静态托管的目录越界判断必须放行 `dist` 本身**：`path.relative(DIST, DIST)` 返回的是**空串**，
  第一版把空串当成"越界"，于是请求 `/` 直接 403 —— 用户看到的现象就是"index.html 打不开"。
  越界只可能是 `..` 开头或绝对路径。
- **客观事实与讲解分开来源**：音标、词性、大纲标注这些**可判定**的东西来自词典，讲解来自模型。
  两者冲突时以词典为准，并把冲突显式写在卡片上（"音标已按词典校正""词典还标了 v."）——
  用户真正怕的不是 AI 讲得不深，是它一本正经地把 /əbˈdʒekt/ 标成名词读音。
- **词典是加分项，不是依赖**：查不到 / 超时 / 连续失败熔断，一律静默降级为纯 AI。
  外部接口挂了不该让"查词"这件事本身失败。
- **`l.i` 有时是字符串、有时是数组**：词典接口的释义字段两种形态都出现过，
  早期版本只用 `String()` 取，数组一律变空串 —— 音标搭配都正常、**释义全是空的**，
  卡片看着没毛病，实际一个字都没核对。测试里专门有一条钉这个。
- **`saveToBook` 必须能显式传"基础列表"**：`books` 是本次渲染的闭包快照，而"新建单词本并加入"
  是在同一个事件里先 `createBook` 再存词条 —— 沿用闭包会让 `upsertEntry([], id, entry)` 返回空数组，
  紧接着把**刚建好的本子抹掉**。表现就是"按钮点了没反应"，e2e 抓到的就是这个。
- **侧边栏的本子项"打开/收起"要连 `view` 一起判**：只看 `activeBookId` 时，
  刚存完词（本子已是 active）再从搜索页点它会被 toggle 成空，页面原地不动 —— 又是"点了没反应"。

## 部署：让别人也能用网址打开

先说结论，因为这里最容易走错：

| 方案 | 能跑后端吗 | 适合 | 坑 |
| --- | --- | --- | --- |
| **GitHub Pages** | ❌ 只能放静态前端 | 想把前端挂个公网地址 | 后端必须另找地方，否则查词/账号/同步全没有 |
| **Render 免费档** | ✅ | 个人自用、发给朋友 | 15 分钟无请求会休眠（下次打开等 30~60 秒）；磁盘临时，**必须配 Upstash** |
| 自己的 VPS / 家里电脑 + Cloudflare Tunnel | ✅ | 想完全自己掌控 | 要自己管进程、证书、备份 |

**为什么 GitHub Pages 一个人扛不下来**：查词要拿服务端的 Key 去调模型（Key 放前端等于公开），
账号与云同步要持久化数据 —— 这两件事都要求一个能跑 Node 的后端。GitHub Pages 只发静态文件。

### 只部署后端（推荐，一步到位）

1. https://dashboard.render.com → New → **Blueprint** → 选本仓库（它会读根目录的 `render.yaml`）
2. 填环境变量：`AI_API_KEY` 必填；`UPSTASH_REDIS_REST_URL/TOKEN` 强烈建议
   （不填的话账号功能会自动关闭、同步数据重新部署就没）
3. 部署完拿到 `https://vocabulary-book-xxxx.onrender.com` —— **这个网址发给别人就能用**，
   前端由后端一起托管，不需要第二处部署

### 后端 + 前端分开（想要 GitHub Pages 的网址时）

1. 先按上面部署后端，在 Render 里设 `ALLOW_ORIGIN=https://<你的用户名>.github.io`
2. 仓库 Settings → Pages → Source 选 **GitHub Actions**
3. 仓库 Settings → Variables → Actions 新建 `VITE_API_BASE` = 后端地址
4. 推一次 `main` 即自动发布（`.github/workflows/deploy-pages.yml`）

⚠️ 少了第 1 步的 `ALLOW_ORIGIN`，浏览器会在预检阶段拦掉所有请求 —— **页面看着正常，实际什么都查不出来**。

### 公开之前请务必想清楚：谁能用你的 Key

这是部署到公网**唯一可能让你花钱**的地方，两种选法各有代价：

| 选法 | 访客体验 | 你的风险 |
| --- | --- | --- |
| `ALLOW_SERVER_KEY=0`（`render.yaml` 默认） | 每人要自己在「AI 设置」里填 Key | 零。别人花自己的钱 |
| `ALLOW_SERVER_KEY=1` + `AI_API_KEY` | 打开就能用 | 网址一旦被转发出去，额度就是你买单 |

选了第二种就**一定要设 `DAILY_JOB_LIMIT`**（`render.yaml` 里给了 300）。
限流管的是"每个 IP 每分钟"，换个 IP 就能接着刷；每日额度是唯一真正兜住账单的东西，
到顶后访客会看到一句明确的提示 —— 并且**填自己的 Key 就能立刻继续用**。
在 `/api/status` 的 `budget` 字段能看到今天用掉多少。

## 环境变量

见 `.env.example`。最常改的几个：

| 变量 | 说明 |
| --- | --- |
| `AI_BASE_URL` / `AI_MODEL` / `AI_API_KEY` | 任意 OpenAI 兼容接口 |
| `DICT_PROVIDER` | 词典核对：`youdao-web`（默认，免费）/ `youdao-open`（官方付费）/ `off` |
| `YOUDAO_APP_KEY` / `YOUDAO_APP_SECRET` | 走官方开放平台时的凭据 |
| `DICT_BASE_URL` | 词典接口地址，默认 `https://dict.youdao.com`（可指向自建镜像） |
| `PORT` | 后端端口（默认 8790） |
| `ALLOW_SERVER_KEY` | 设 `0` 强制访客自带 Key（公网开放时建议设 0） |
| `ALLOW_ORIGIN` | 前后端分开部署时的跨域白名单 |
| `UPSTASH_REDIS_REST_URL/TOKEN` | 配了才会启用账号 + 持久云同步 |
| `KV_PREFIX` | Redis 键命名空间（默认 `vb:`）；**多个应用共用一个库时必须各不相同** |
| `JOB_MAX_COUNT` | 任务记录条数上限（默认 2000），超过按最旧的淘汰 |
| `RATE_LIMIT_PER_MIN` / `MAX_INFLIGHT_JOBS` | 限流与并发闸门 |
| `DAILY_JOB_LIMIT` | 每日额度（0=不限，只算用服务端 Key 的请求）；公网开放时**务必设一个** |
| `ALLOW_SERVER_KEY` | `0` = 访客自带 Key（不花钱）；`1` = 可用服务端 Key |
